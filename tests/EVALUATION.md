# 语义评估与报告边界

自动测试只检查包结构、缺陷检测和 ZIP 完整性。它们不运行语言模型，不给写作质量打分。

## 一次可复查的评估

1. 记录技能版本/提交、客户端、模型、日期、采样设置、启用的其他技能及可访问工具。不能取得的信息如实写未知。
2. 从 [regression-prompts.md](regression-prompts.md) 选实际相关任务；将“指令”与所需材料交给模型，评阅时再使用成功/失败信号，避免将预期答案当输入。
3. 保存完整输入与原始输出，不能仅保存自己润色过的结果。使用虚构测试材料或获准公开的材料，不上传私人稿件。
4. 若要声称改善，与未加载技能的同模型同设置输出作比较。单次输出只说明该任务的表现，不能量化总体提升。
5. 根据任务完成度、事实/观点保留、推理、语体和证据强度逐项记录具体观察；失败要保留并说明，不用一个总分掩盖编造数据等严重问题。
6. 独立评阅或多次运行可提高可信度，但本协议不自动授权调用付费服务、创建子代理或发布评测材料。

## 记录格式

| 字段 | 内容 |
| --- | --- |
| skill_version / commit | 实际版本与提交 |
| model / client / settings | 实际运行环境，不确定处标未知 |
| case_id / input | 测试编号和完整输入或受控本地位置 |
| output | 原始输出或可追溯文件 |
| evaluator | 自评、人工或独立模型，明确区别 |
| findings | 保留与违反的要求，引用具体句子 |
| status | passed / failed / not_run；只针对这个用例 |

本仓库提供 20 组任务与评估方法，不把示范答案、静态审阅或包测试写成已完成的独立行为评测。
